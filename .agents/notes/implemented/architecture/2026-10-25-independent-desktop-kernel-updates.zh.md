# Agent Note: 在打开实例数据前准备独立的 Desktop 内核更新

Status: implemented

[English](2026-10-25-independent-desktop-kernel-updates.md) | 中文

## 问题

社区插件可能要求比 Desktop 安装包更新的 DSH。在运行中的 Host 下替换包，会在进程未重启时改变模块身份和原生依赖。Profile 快照无法保护实例 home 其他位置的会话文件和插件数据。

## 决策

外壳拥有独立内核存储，在应用启动时检查官方 npm `latest` 通道。自动准备默认开启，可在应用设置中关闭。准备过程在内置回退版本旁安装精确版本，复制外壳的私有无端口桥接，记录最终文件清单，并启动带有三个基础插件的临时实例。只有 HTML 加载和设置 RPC 成功后才发布版本选择。运行中的实例继续使用应用启动时选定的内核，准备好的更新于下次启动应用时生效。已选择版本会按文件清单校验；外壳桥接或内置执行工具变化时重新准备。不支持的版本准备失败，保留原有选择。

停止的本地实例切换运行时身份前，外壳将其完整 home 复制到同级恢复目录。每个已注入插件按原精确版本为所选内核重新准备，保留配置和禁用状态。不兼容时拒绝启动，不改选其他插件版本。恢复备份包含实例内的会话和插件文件，但无法涵盖外部路径、浏览器分区和远程服务器数据。新版本写入数据后返回旧代码需要配套恢复数据，外壳不提供只降级代码的按钮。

外壳原生市场继续使用与 dshmarket 共享的社区目录，统一拥有版本选择、本地安装和实例分发，不挂载 dshmarket 的 Web 后端。符合条件的本地实例只首次安装 `dsh-at-file`、`dsh-context` 和 `dsh-cost-meter`。初始化中断后重试缺失安装；完成标记保证之后尊重用户删除和禁用，已有版本保留。远程内核和基础插件安装仍归服务器管理。

插件准备保持关闭 Host peer 自动安装。Host 包通过所选运行时解析，必需的私有 peer 与下载包声明的私有依赖通过 pnpm package extensions 补齐后再校验依赖图。这可以处理 registry 元数据遗漏下载包内依赖的情况，同时避免借用祖先项目依赖。预发布内核参与声明的 semver 范围匹配，不兼容的范围仍拒绝部署。

已发布的 `dsh-at-file@0.6.3` 浏览器包从停用的 `dsh-client-runtime/client` 入口导入 `createSnapshotStore`。精确版本适配将该导入替换为 `dsh-client-store`，同步修改对应 peer 和客户端注入声明；未知导入模式会使安装失败。这使插件使用当前内核的共享 store 实现，避免安装过时运行时依赖图；其他版本不改写。

桥接适配旧版流接口以及新版 Gateway 显式传入的 owner Peer、输入迭代器和取消信号。双向流通过逐帧确认的 Fetch 请求发送输入；第二个未完成的写入会被拒绝，取消输出会释放等待中的输入。内核准备要求在发布前收到事件流就绪帧。浏览器传输测试覆盖有序双向输入、消费确认，以及输入生产者等待时的取消。

本决策部分取代[内置运行时决策](2026-09-08-desktop-bundled-runtime-and-external-plugins.zh.md)中的发行版本耦合，以及[插件库决策](2026-10-23-shell-plugin-library-and-instance-injection.zh.md)中的运行时变化后显式重新注入。两者仍拥有回退包构建、包身份、独立部署和事务归属依据。[原地 Profile 决策](2026-09-09-desktop-in-place-profile.zh.md)、[市场决策](2026-10-17-desktop-plugin-market-and-profile-recovery.zh.md)和[实例管理器决策](2026-09-16-desktop-instance-manager.zh.md)仍保留独立的锁、目录、恢复和 SSH 依据，没有被完全取代的记录。

## 考虑过的替代方案

**在运行中的实例内更新包。** 这可能在同一进程中混用多代包，并使每个实例各自管理安装。

**将 Profile 回滚视为内核降级。** 它不包含会话代次和 Profile 之外的插件数据，无法建立旧读取器的兼容性。

**嵌入 dshmarket 安装器。** 其 Web 路由和独立包操作与无端口外壳的统一安装归属冲突。

## 后果

独立发行版本、插件依赖图和完整 home 备份占用磁盘空间，不自动回收。首次准备需要访问 npm 并执行获准的原生构建。临时启动能验证传输和插件组合兼容性，不能证明任意第三方迁移或真实模型行为。所属目录测试覆盖延后选择、准备失败、并发请求、基础插件重试和删除、同版本重新注入、保留启用状态及完整 home 备份。签名安装包升级、macOS 原生执行、插件外部副作用、远程服务器和模型提供方验收仍属于发行验证要求。

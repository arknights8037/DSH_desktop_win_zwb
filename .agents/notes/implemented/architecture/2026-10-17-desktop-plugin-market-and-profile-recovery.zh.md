# Agent Note: 审阅社区插件并恢复失败的 Profile 变更

Status: implemented

[English](2026-10-17-desktop-plugin-market-and-profile-recovery.md) | 中文

## 问题

社区发现不能把目录命令变成桌面权限。可变 npm 标签可能在审阅与安装时解析出不同版本。包操作或 Host 启动失败可能导致实例无法使用，只恢复配置不能恢复已安装依赖的字节。

## 决策

桌面端使用与 dshmarket 共用的 awesome-dsh-plugin JSON 格式。发现功能使用支持系统网络设置的 Electron HTTP 传输，校验外部字段，不执行目录命令。jsDelivr 上发布的目录 JSON 作为传输备用来源，显示实际来源与发布方日期。运维指定的 HTTPS 来源替换两个默认来源。仅 Git 源条目保持可见，但不会获得另一套安装器。

只读 npm 预检将标签解析为确切版本，针对内置运行时比较引擎与 peer 要求，区分未知要求和明确不匹配。单次使用且会过期的标识将计划绑定到外壳插件库窗口。主进程独立于界面控件拒绝不匹配及不支持的包。可选作者权限和目录扫描能力只描述访问行为，不授予或限制权限。`dshmarket` 包需要 HTTP Host，且拥有独立的包变更流程，因此桌面端接入共享目录，不将保留 Profile 交给该安装器。

每次插件变更在包锁内停止 Host，将完整 Profile 复制到其外部的私有快照，不包含持有中的锁。普通文件独立复制，符号链接和 Windows junction 保持链接。写入前，完整快照替换前一次快照。包操作、校验、构建或启动失败时，将文件恢复到原 Profile 位置，等待原 Host 启动。恢复失败时同时报告两个错误和快照位置。恢复成功时管理器重新连接 Host 视图，同时保留操作失败的诊断。

本决策部分取代[原地 Profile 决策](2026-09-09-desktop-in-place-profile.zh.md)对显式插件变更的失败保留行为。该记录继续负责启动与发布校准、包锁、待构建重试，以及不引入激活日志的理由。[内置运行时](2026-09-08-desktop-bundled-runtime-and-external-plugins.zh.md)和[实例管理器](2026-09-16-desktop-instance-manager.zh.md)决策继续负责运行时与隔离职责。没有记录被完全取代或归档。

[外壳插件库决策](2026-10-23-shell-plugin-library-and-instance-injection.zh.md)负责安装位置及本地与 SSH 的显式注入；目录预检和本地 Profile 恢复仍由本记录负责。

## 考虑过的替代方案

**直接加载 dshmarket 安装器。** 它的 Web 路由和独立包操作无法维持桌面端的无端口传输、实例归属和事务锁。

**恢复 package.json 后重新安装。** 恢复将依赖网络和生命周期构建，无法还原被修改的包文件。完整复制以磁盘空间和复制时间为代价，无需再次运行包管理器即可恢复。

**通过崩溃日志准备并激活替代 Profile。** 这会增加目录迁移、激活及中断事务恢复。原地修改配合变更前复制可处理捕获到的错误，无须第二个活动 Profile 或日志格式。

## 后果

仅保留最近一次完整快照，其中的普通文件使 Profile 所需磁盘空间大致翻倍。外部链接目标、共享会话和 Profile 外的副作用无法恢复。断电和强制终止后需要手动恢复；发布校准与破坏性重置保留各自的语义。备份不是沙箱，也不是对社区代码的安全认可。

归属于桌面端的界面预期输出覆盖双语安装详情。聚焦测试覆盖仓库格式错误、标签、未知版本要求、阻止安装的计划、绑定外壳插件库且单次使用的确认、取消及搜索。真实子进程夹具覆盖包操作、校验、构建及启动失败，配置与依赖字节恢复，外部链接保留，恢复失败和独占包归属。这些检查不能验证任意第三方插件的行为，也不构成签名应用的发布验收。

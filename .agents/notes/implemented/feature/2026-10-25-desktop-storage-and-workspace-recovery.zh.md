# Agent Note: 桌面存储查看与工作区失败恢复

Status: implemented

[English](2026-10-25-desktop-storage-and-workspace-recovery.md) | 中文

## 问题

桌面管理器无法显示本地数据的位置，也无法显示设置、实例、包缓存和插件库分别占用的空间。工作区选择在连接阶段失败时会直接回到选择器，不显示失败原因，也没有重试入口，因此不可用的工作区看起来像是页面没有打开。移除实例时也没有明确选择保留还是永久删除本地 home 的入口。

## 决策

桌面设置增加只读的“存储”页。管理器 IPC 操作递归返回管理器自身文件、本地实例数据、pnpm 缓存和插件库的字节数，并返回每个本地实例的占用。管理器自身的统计排除实例目录和插件库目录，因此页面总数等于四个分类之和。目录遍历忽略符号链接，缺失目录按空目录处理。每个分类都可以在操作系统文件管理器中打开；该页面不会删除会话或其他存储数据。移除本地实例时默认保留其 home；确认对话框可以在 Host 停止后请求删除该实例 home，远程实例数据不能在本机删除。清理会删除所属文件和目录链接但不跟随链接目标，只有清理成功后才移除注册表条目。

工作区选择保留原有连接生命周期，并在会话首页记录失败的选择。错误文本会显示给用户，同时提供重试操作，重复选择同一个工作区。之后成功选择其他工作区时，旧错误会清除。

## 曾考虑的替代方案

**在首个存储页面加入删除和清理控制。** 否决：存储查看不应混入缓存和插件库的破坏性保留选择。实例移除确认框负责范围更窄的本地 home 删除，存储页保持只读。

**只记录工作区失败，不修改会话界面。** 否决：管理器和连接日志不会在用户被阻塞的位置显示，也没有直接的重试操作。

**自动重试工作区连接。** 否决：自动重试可能在用户没有明确操作时重复认证、网络或配置失败。页面显示真实错误，并由用户决定何时重试。

## 后果

大型目录的存储读取可能需要时间，因此页面提供加载中和不可用状态。字节数是某一时刻的快照，不代表预留空间，也不预测未来增长。工作区失败保留为临时界面状态；底层 session 与连接事件保持不变。

## 测试

管理器渲染测试覆盖存储页、分类总量、本地实例呈现和打开目录操作。会话骨架测试覆盖失败消息和重试控件。桌面与会话的 TypeScript 检查通过，桌面启动、管理器渲染和会话聚焦测试也一起通过。

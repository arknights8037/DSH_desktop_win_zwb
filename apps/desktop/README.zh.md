# DshManager

## 概要

Windows 桌面应用管理相互独立的本地和 Linux SSH Harness 实例。每个标签页包含该实例的完整 Web UI，包括项目和对话。软件偏好和模型凭据应用于已连接及后续连接的实例，各实例保留自己的插件、会话和专有配置。

## 实例

首次启动时，选择**创建本地实例**或**连接远程实例**。标签页后面的 **+** 提供新建本地或 SSH 连接，以及已保存实例的快速连接入口。**设置 → 实例管理**打开已保存的连接列表，可打开、编辑或移除配置。再次打开已有标签页会聚焦其当前视图。

工作区编辑位于左侧栏工作区目录行的 **⋯ → 编辑工作区** 菜单。注入的编辑器在同一个工作区身份下保存名称和最多 32 个源文件夹。第一个文件夹是新会话的工作目录，其他文件夹进入模型上下文，但不改变沙箱权限。已有会话的目录和历史保持原样。移除工作区只移除其登记。

Desktop 覆盖配置禁用内核工作区注册表，并挂载 Desktop Host 中由外壳拥有的提供方。Profile 解析器使用 Desktop runtime 清单，因此外壳拥有的包可供注入覆盖层使用，而无需加入实例的插件依赖。它保留现有工作区数据域和记录格式。文件夹读取和编辑操作使用外壳的 `/.dsh/workspace` 路由。外壳拥有的 DOM 适配器向可识别的目录菜单添加编辑操作，弹窗使用 `shell.overlay`。不支持的菜单结构不会注入操作。替换内核仍需验证启动和 UI 兼容性。

每个本地实例拥有独立的 Host 进程和 Harness home。本地实例共享应用内不可变的运行时包，可写 profile、对话、设置、浏览器存储和插件安装相互隔离。新实例不会导入已有 CLI 或 Desktop 数据。

右键标签页可重命名、重新连接、查看生命周期日志或关闭标签页。重命名直接在标签内编辑已保存的实例名称：Enter 保存，Escape 取消，实例保持运行。带齿轮图标的**设置**打开可复用的独立标签页，全高侧栏分为应用、实例管理、外观、快捷键、模型凭据、DSH 设置、存储和插件，右侧内容独立滚动。设置与实例标签可相互切换，实例保持连接；关闭设置后返回当前实例或欢迎页。无原生边框的窗口在设置右侧提供最小化、最大化／还原和关闭按钮，拖动标签栏空白区域可移动窗口。共享主题、内容字号、语言、Agent 忙碌时的 Enter 行为、窗口快捷键和模型 API Key 均可在未连接实例时保存。

软件设置是统一来源。已连接的实例通过现有 DSH API 接收变更，新建或重新连接的实例继承已保存的值。实例偏好不会更新软件偏好。**DSH 设置**管理轮次显示方式、Agent 模式选择、默认预设、默认模型提供方与模型 ID，以及 DeepSeek 的协议、API 地址、凭据名称、输出 Token 上限与推理强度。两个默认模型字段同时留空时保留各实例的模型选择，否则同时填写已存在的提供方路由与模型 ID，作用于后续创建的 Agent。**保存并应用**可离线保存，覆盖实例支持的字段并保留其他配置；同一命名空间内的字段原子更新。预设 ID 必须在各实例中存在。在原生页面修改受管理字段后，重新连接或下次修改软件设置时会再次覆盖。插件配置仍归实例管理。

每个共享控件显示已连接实例的实际命名空间与字段，并标明不支持或只读状态。外壳从实例公布的 schema 获取选项和数值范围，在下发前校验保存的值。实例允许时，推理强度可填写提供方特有的字符串。被拒绝的写入会显示错误，不会关闭连接。窗口操作、快捷键、存储及注入动效归外壳管理；实例公布原生动效设置时也会同步该字段。

**模型凭据 → 添加来源**可管理多个独立的 OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages 接口，同一协议也可添加多个来源。提供商模板涵盖 OpenAI、Anthropic、DeepSeek、Google Gemini、OpenRouter、阿里云通义千问、Moonshot/Kimi 和本地 Ollama；所有地址均可编辑。每组来源具有显示名称、API 基础地址、选定的模型 ID、上下文与输出 Token 上限，以及独立加密的密钥。打开已配置的来源或完成地址、密钥字段后会自动获取模型列表；**获取模型**可重试。从列表中最多选择 256 个模型，也可在接口不支持列举时手动填写。获取列表不能确认生成权限或账户额度。已配置的密钥显示状态和**更换凭据**操作，输入框在更换前隐藏。**设为默认模型**可选择已保存的来源和模型，供之后创建的 Agent 使用。地址填写服务的基础路径，而非完整请求路径；模型 ID 必须与接口支持的值一致。这些声明通过实例的 `llm-pi-ai` 设置注册为独立路由。编辑时密钥留空会保留原值。删除来源会移除其受管理路由和密钥，离线实例在重连时同步删除，其他提供方保持不变。若删除的是当前默认来源，受影响的实例会恢复组合配置中的默认模型。已有独立凭据名称仍可在**独立凭据 / DeepSeek 密钥**中管理。模型生成依赖所配置的服务，保存定义或获取列表均不能确认生成能力。

**外观**支持预览本地 PNG、JPEG 或 WebP 背景图，可选择颜色蒙版、调整蒙版强度与面板不透明度。输入图片最大 20 MB，缩放至最长边 1600 像素以内并压缩至 512 KB 以内。分区配色涵盖全局背景、顶部标签栏、侧栏、聊天内容、输入框、强调色、主要文本和次要文本。预设与带版本号的 JSON 配色导入／导出共用这些分区，导出仅包含颜色。**保存并应用**持久保存预览并下发至已连接实例；**取消**恢复已保存外观，**恢复默认**先预览基础主题，保存后生效。单个颜色可以跟随基础主题。外壳在透明实例视图后统一绘制一次壁纸，并控制实例分区配色。实例侧栏的设置按钮打开软件设置标签页，首次使用引导仍在实例内。远端客户端需具备匹配的语义配色 token 才能完整覆盖外观；旧版导航代码保留自身设置按钮。设置同步被拒时仍独立显示错误。

**外观 → 流畅动效**控制外壳内置动效插件，默认开启。开关即时保存并应用于外壳和已连接的本地或 SSH 实例视图，无需重启或进入插件页配置。菜单和弹窗轻柔进入，设置分区淡入，控件使用短促的颜色过渡和按压反馈。插件遵循系统的“减少动态效果”偏好，流式文本和会话滚动保持原有行为。关闭后移除这些附加效果，实例原有动画仍然保留。旧版偏好文件默认启用动效。远端覆盖范围取决于标准按钮、菜单和弹窗语义。

外观草稿同时预览在外壳、现有及新打开的实例视图中，不写入软件或后端设置。取消或重载管理器会恢复已保存外观。启用壁纸后，设置卡片和实例行共用内容区域底色，不额外叠加不透明层。当前标签共用顶部栏底色，欢迎卡片使用内容区不透明度，来源文本框使用输入区配色。菜单和弹窗保留实色底板，保证可读性。

桌面外观适配层将凸起和浮动按钮的底色、悬停色、边框及背景卡片映射到已保存的配色，包括新会话按钮。启动、实例连接和插件操作共用窗口居中的轨道加载动效，以阶段文字代替横向进度条。动效遵循减少动态效果的系统偏好；管理器画面还遵循已保存的动效选项。

桌面内置外观适配层在每次加载后自动向本地和 SSH 实例页面注入展示样式。内核更新不会覆盖该适配层或已保存的壁纸设置，无需为实例安装插件。主内容列和侧栏列各只绘制一次所设不透明度的底色，嵌套页面背景保持透明，使用旧版基础背景 token 的客户端也适用。实例设置页隐藏解释性文本和参数提示，同时保留状态和告警信息。此兼容规则依赖设置页 DOM 类名，内核更新后需要检查；其他外观兼容性依赖 DSH 语义 token 和具名 UI 槽位，采用其他样式的第三方页面可能保留自身背景。

模型 Key 使用提供方的凭据引用名，例如 `DEEPSEEK_API_KEY`。软件通过操作系统加密 Key，并将其发送到各个已连接的本地或远程实例的 DSH 凭据存储。已保存的值不会返回设置表单。移除软件管理的 Key 后，离线实例在重新连接时也会移除它。SSH 认证单独处理，不持久化保存。

聚焦快捷键输入框并按下组合键即可录制，Backspace 或 Delete 可禁用该操作。重复绑定会被拒绝，**恢复默认**可重置全部绑定。管理器或实例拥有焦点时均可使用快捷键，它们不注册为系统全局快捷键。

## 插件目录与安装

在打包后的桌面外壳中打开**设置 → 插件**。页面不显示解释性文本和插件介绍，带内边距的卡片将操作按钮放在独立列。左侧显示社区市场、搜索、分类筛选和 npm 查询，右侧显示已保留版本、安装审阅、目标选择和实例管理；窄窗口将市场放在管理区域上方。可将市场筛选为可安装或已添加的插件，清除筛选，或通过已添加条目的**管理**定位插件库版本。已添加条目也提供**检查新版本**，添加新版本仍需确认。目标选择位于版本列表前，若选定实例不可用，必须重新选择。安装期间仍可搜索、筛选和使用设置导航。包来源、完整性和恢复路径保留在可展开的审阅详情中。没有实例时也可审阅并保留精确 npm 版本。本地依赖图在外壳插件库中按需准备，远端专用插件不必先在 Windows 安装。各实例独立保留部署和配置，添加或移除库中版本不会更新已有副本。

新建本地实例在首次符合条件的初始化中安装 `dsh-context@0.77.0` 和 `dsh-cost-meter@1.9.41`，保留已有版本和禁用状态。安装中断后会在启动前重试；完成后，用户移除的插件不会重新安装。两个插件共用外壳插件库和实例管理入口。

`dsh-at-file@0.6.3` 依赖已退役的客户端 API，因此不再自动安装。Desktop 不会改写插件导入来模拟这些 API。已有注入插件保留原精确版本；不兼容的包会使内核准备停止并报告错误。下载包内声明但 registry 元数据遗漏的私有依赖会在依赖校验前安装。

详情展示解析后的版本、npm 来源、许可证、仓库、完整性、生命周期脚本，以及相对于外壳运行时的 engine 和 peer 要求，供用户参考。缺少 bundle 声明会阻止加入插件库。目标实例在准备依赖时校验兼容性，不允许替换 Host 拥有的包。目录中的能力和权限属于发布者声明，并非沙箱保证。

确认会消耗一份有效期为 15 分钟的外壳插件库计划。打开本地或 SSH 实例，在插件库中选定它，再选择**注入 / 应用版本**。操作会准备独立副本，仅重启该实例，并保留已有插件配置和启用状态。本地实例窗口保留启用、移除和恢复操作。

**设置 → 插件**默认开启**自动升级兼容的插件**。本地实例启动前，Desktop 检查 npm `latest`，每次打开软件后，同一已安装插件清单检查一次。仅安装版本更高、声明的 DSH 和运行时要求兼容且无部署阻碍的版本。新版先在外壳插件库中准备，再修改实例，保留配置和启用状态。同一面板显示结果及跳过版本的诊断。注册表或候选版本准备失败时保留原版本。关闭选项影响后续启动，不强制重启运行中的实例。SSH 插件升级仍由服务器管理。

本地插件变更将完整 Profile 备份到 `<instance-home>/desktop/profile-snapshot`，排除正在持有的锁。手动包操作、校验、构建或启动失败时恢复副本并重试原 Host，无需重新安装包。自动替换共用一份快照；替换或依赖图校验失败时恢复 Profile，并保持启动停止。随后 Host 启动失败也会保持实例停止，可通过快照手动恢复。快照需要额外磁盘空间，不恢复共享会话、外部文件和插件在 Profile 之外的副作用。强制结束或断电需要手动恢复：停止实例并关闭管理器，保留失败 Profile，再将快照内容复制到 `profiles/desktop`。Profile 重置仍为破坏性操作，不创建新备份。本地插件库缓存按运行时区分；内核变化时，除已选定兼容升级的插件外，按原精确版本重新准备注入插件。已有不兼容插件仍可能阻止启动；自动更新不会降级包，也不会重建已退役 API。

远端注入在后台调用已连接实例的认证 Web API，所有操作入口仍位于全局软件设置。SSH 仅承载连接和进程启停。远端 DSH 必须包含插件部署 API，且 PATH 中需有 pnpm。服务端在禁用生命周期脚本的情况下准备全新依赖图，校验 Host peer 和运行时要求，再安排选定版本在重启时生效。重启前不会改变当前清单和插件链接。若启动在就绪前失败，下次启动会根据日志恢复。准备失败保留当前进程。旧服务端会提示更新，不会退回 SSH 安装脚本。

发现功能使用 [awesome-dsh-plugin 目录](https://awesome-dsh-plugin.com)，与 [dshmarket](https://github.com/dsh-market/dsh-market) 共用数据。主站失败时，桌面端通过 jsDelivr 请求已发布的 `dsh-plugin-catalog` JSON，显示实际来源与发布方日期，不用内置目录或磁盘缓存替代。运维可设置 `DSH_DESKTOP_PLUGIN_CATALOG_URL`，指定不含凭据的 HTTPS JSON 来源，此设置替换两个默认来源。请求失败时可重新加载。不会执行目录中的安装命令字符串。仅 Git 源的条目仍可浏览和打开仓库链接，桌面安装只接受 npm 仓库包。无端口桌面 Host 不加载 `dshmarket` 的 Web 路由或独立包管理器。

## 内核更新与数据恢复

**设置 → 应用 → DSH 内核**检查官方 npm `latest` 通道。自动准备初始开启，关闭后可手动检查并选择**准备更新**。更新独立安装，必须通过临时 Host、基础插件、Web 资源、事件流就绪和设置 RPC 验证。所选内核在应用退出前保持不变；更新就绪后退出并重新打开应用，单独重启实例不会切换内核。准备失败保留原有选择。外壳安装包仍单独管理，此入口不更新 SSH 内核。

安装版启动时，若内置内核版本等于或高于已保存选择，则优先使用内置内核，避免对同一发布重复下载、复制及临时探测。更新的下载内核仍在启动时校验。运行时内容变化仍执行下述完整 home 备份与插件准备。插件库元数据仅在其固定运行时所有者的生命周期内保留；插件选择和已完成安装记录仍从磁盘读取。启动进度更新现有文档，不重启动效或再次导航。

实例首次使用变化后的运行时前，Desktop 将完整 home 复制到 `<instance-home>-kernel-backups/backup-*/home`；`complete.json` 标识已完成备份及其版本。home 内的配置、会话、凭据和插件文件保留，浏览器存储和 home 外的文件不在其中。备份包含敏感数据，需要额外磁盘空间，保留供手动恢复，不自动还原或回收。恢复时先停止实例并关闭 Desktop，保留变更后的 home，再将选定的完整备份恢复到原 home 路径，并配套使用兼容内核。只切换旧代码不能使新版会话或插件数据变得可读。

实例连接时逐字段判断设置兼容性。默认模型推理优先使用 `agent-default-model.reasoningEffort`，不存在时使用 `llm-deepseek.reasoningEffort`。其他命名空间独立判断；存在新版默认模型命名空间，不会禁用实例仍公布的对话显示、预设、协议、接口或外观设置。不支持的选择仍保留，供兼容实例使用。

<a id="remote-connections"></a>

## 远程连接

远程实例需要一个已安装 DSH 和 tmux 的 Linux SSH 账户。填写主机、SSH 端口、用户名、密码或私钥认证方式，以及 DSH 可执行文件路径。密码和私钥口令在连接时输入，仅保留在管理器进程中，不会写入注册表。配置保存私钥路径，不保存私钥内容。

首次连接需要确认服务器指纹。指纹变化时连接被阻止。管理器按主机和端口固定服务器密钥，修改信任记录前应核实变化原因。第一版使用明确的主机信息，不导入 SSH 配置别名或跳板机。

远端数据目录留空时使用 `~/.local/share/dsh-manager/instances/<id>` 下的独立目录，也可填写专用的绝对路径或 `~/` 路径。已存在但不包含本实例归属标记的目录会被拒绝。不要使用已有的个人 Harness home。

管理器在所属 tmux 会话中启动 `dsh --profile web --no-open --port 0`。通过 SSH 读取带认证信息的启动地址，并将本地回环端口转发到远端回环监听器。远端实例提供与其版本配套的 Web UI。认证 URL 不进入管理器日志或配置。

SSH 断开时显示远端进程状态未知。重连会先检查所属 tmux 会话，再决定是否启动进程。显式**停止实例**会核实目录和 tmux 归属后再停止该会话。启动失败时可检查远端实例目录中的 `.manager-startup.log`，该文件包含认证信息，不应分享。

<a id="lifecycle-and-storage"></a>

## 生命周期与存储

Windows 安装程序在首次安装时提供独立的数据目录选择；已有安装保留原选择。**设置 → 存储**保留管理器设置、实例数据、包缓存和插件库各分类的“迁移…”入口，不再显示独立的“迁移数据目录”按钮。迁移会关闭实例并重启应用，在复制和校验所选分类的数据成功后更新目录记录，原目录保留。请先关闭其他共用该 home 的 DSH 应用，并为副本预留空间。外部项目目录和 Electron 浏览器存储保留原位置，凭据仍使用本机加密。

| 操作 | 本地实例 | 远程实例 |
|---|---|---|
| 关闭标签页 | 关闭视图，进程继续 | 断开 SSH，进程继续 |
| 断开连接 | 分离视图，进程继续 | 关闭隧道，进程状态变为未知 |
| 停止 | 停止所选 Host | 通过 SSH 停止所属 tmux 会话 |
| 退出管理器 | 确认后停止本地 Host | 断开连接，远端任务继续 |
| 移除配置 | 停止 Host，默认保留数据；勾选**同时删除本地实例的全部数据**后删除其 home | 忘记连接；远端进程和数据保留 |

注册表和标签页布局保存在 `$DSH_HOME/desktop/agent-manager/instances.json`，软件偏好和加密模型 Key 位于同目录的 `software-settings.json`。本地 home 位于 `$DSH_HOME/desktop/agent-manager/instances/<id>`，每个目录都有独立的保留 profile `profiles/desktop`。浏览器分区按实例 ID 隔离。恢复的标签页在选中时连接，退出应用后需要重新输入 SSH 凭据。

**设置 → 存储**显示管理器设置、本地实例 home、包缓存和插件库的占用，并可在系统文件管理器中打开各目录。移除本地实例时，默认保留其 home；在确认对话框中勾选**同时删除本地实例的全部数据**后，会永久删除实例 home 中的对话、设置、插件和文件。此设备不能删除远程实例数据。

远程进程驻留涵盖管理器退出与 SSH 中断，不涵盖服务器重启或管理员强制清理会话。实例运行时不要删除其数据目录。

<a id="development-and-packaging"></a>

## 开发与打包

请先在打包版中准备并选择内核，并保留 `.desktop-build/targets/` 下目标平台配套的 Node.js 和 pnpm 工具。在仓库根目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm run dev:desktop
```

桌面构建成功后，可通过 `pnpm run start:desktop` 跳过构建直接启动；`dev:desktop` 只构建外壳。开发数据保存在 `apps/desktop/.desktop-build/development/home`。启动时读取 `$DSH_HOME/desktop/agent-manager/kernels` 中已选内核，检查 npm `latest`，并在打开窗口前准备任何更新版本；检查或准备失败时拒绝启动。`DSH_DESKTOP_KERNEL_HOME` 可以独立于开发数据指定其他内核 home。启动器将 `HTTPS_PROXY` 或 `HTTP_PROXY` 传给 Electron 注册表请求及包管理器子进程。本地插件安装和注入使用当前内核。旧源码链接 Profile 在断开包容器前备份完整 home；无法识别的外部包需要先恢复再迁移。

真实 Electron 冒烟测试使用临时 home 启动两个本地 Host，验证共享偏好和测试凭据的继承，操作标签页与快捷键，最后停止两个进程：

```powershell
pnpm exec tsx apps/desktop/scripts/smoke-manager.ts
```

生成未签名 Windows 测试安装包：

```powershell
$env:DSH_DESKTOP_APP_ID = 'dev.dsh.agentmanager'
pnpm run package:desktop:win:x64:unsigned
```

DshManager V0.1.2 安装包输出到 `apps/desktop/.desktop-build/targets/win-x64/unsigned-artifacts`。应用版本独立于内置 DSH 内核版本，内核版本固定在 `apps/desktop/config/kernel-release.json`。正式构建在隔离临时目录中安装对应版本的已发布 npm 包；DSH 源码包不属于构建输入。Desktop Host 和 Electron 外壳源码使用这些已安装包的声明编译，Host 通过注入式插件提供外壳 API。复制资源前，electron-builder 校验内核版本、第一方包版本、平台、文件清单和已准备的工具版本；陈旧资源会阻止打包。官方外壳安装包更新器关闭，独立内核更新使用应用设置。应用和安装程序图标使用 [DeepSeek 官网的鲸鱼 favicon](https://www.deepseek.com/favicon.ico)，转换为 PNG 和多尺寸 Windows ICO；品牌素材归 DeepSeek 所有。

<a id="implementation"></a>

## 实现

主进程拥有实例注册表、每实例运行时控制器和隔离的 `WebContentsView`。本地请求沿用现有分帧管道传输，并按浏览器分区绑定。SSH 实例使用 `ssh2`，其可选原生加速构建被禁用，采用标准 JavaScript 实现。

内置运行时完整解压到 `resources/dsh`，子进程、目录复制和原生依赖解析均使用该真实目录。外壳和渲染器仍位于 ASAR。Windows 安装程序显示解压进度和安装详情。内核与插件准备显示当前阶段和包名；有计数时表示已完成包数，无法计量的工作显示为进行中。

Windows 上的**设置 → 应用 → 打开诊断日志**选项行通过“打开目录”按钮打开 `%APPDATA%/DshManager/logs`。`desktop.log` 记录启动版本、安装阶段、实例状态变化以及脱敏后的错误调用栈和原因链，达到 4 MiB 后轮换为 `desktop.log.previous`。该目录独立于安装位置和可迁移数据目录。启动失败时可直接打开日志目录；日志不可写时明确提示。不主动记录请求正文或凭据，诊断中的 URL 和常见令牌模式会被脱敏。错误已记录不代表恢复或安装成功。

**设置 → 应用 → 启用调试模式（F12）**默认关闭，选择会保留到下次启动。开启后，F12 可切换当前管理器或实例页面的开发者工具；关闭开关会关闭已打开的管理器和实例开发者工具。软件名称和版本同排显示，软件及内核版本使用带边框的标签。下拉选择框统一适配深浅主题，长列表可滚动并根据窗口边缘调整展开方向。

管理器与插件 IPC 要求调用方是所属的确切顶层渲染器。本地 Agent 页面仅收到传输标记，远端页面不注入管理器 preload。实例页面启用沙箱、关闭 Node 集成，不能导航到管理器文档。

生命周期归属与替代方案见[多实例决策](../../.agents/notes/implemented/architecture/2026-09-16-desktop-instance-manager.zh.md)。

<a id="known-limitations"></a>

## 已知限制

此版本不包含跨实例任务聚合、调度、自动部署远程 DSH、服务器重启恢复、密码持久化和 SSH 配置导入。依赖生命周期构建的远端插件需要在实例端另行准备。本地快照和远端副本代次会占用磁盘空间，不自动回收。部署待生效期间不要手动执行包变更。

自动检查覆盖通过 SSH 隧道发送认证 Web 请求、使用真实 pnpm 和测试仓库准备独立依赖、共享 Host 模块身份，以及中断启动后的恢复。它们不能替代在预装 DSH 的 Linux 服务端上使用真实第三方原生依赖和模型凭据开展的验收。

## 开发备注

未签名测试应用使用独立应用 ID，不连接官方发布更新器。

存储页面显示各类数据的字节数及其占统计总量的比例。管理设置、实例数据、软件包缓存和插件库可以分别迁移到不同位置。应用重启后才复制并校验所选类别，成功后切换定位文件，原文件保留供恢复。迁移管理设置不迁移其他类别。软件包操作使用所选的共享缓存。启动及实例加载沿用主界面保存的壁纸、蒙版、配色和动效偏好。
